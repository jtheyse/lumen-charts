# Lumen.Charts API reference

Every public type a chart needs, by namespace `Lumen.Charts` unless stated. All specs are immutable records: build with an object initializer, change with `with { … }`. From 0.25.0 each package also ships its XML documentation beside the DLL (in the NuGet cache, `~/.nuget/packages/<package id>/<version>/lib/net8.0/<assembly>.xml`), so IntelliSense shows member docs and you can read them there.

## ChartSpec

| Member | Type, default | Meaning |
|---|---|---|
| `Title`, `Description`, `Source` | string | Heading, subtitle and source line; title and description are the SVG's accessible name. Default title "Untitled chart". From 0.35.0 each fits the drawing's width less 48, by the library's generous estimate of 11 px text: a description or source too wide goes on over a second line, broken between its ` · ` clauses where both lines then fit and otherwise between the words that set the two lines most nearly equal, past two lines ending in `…`; the plot moves down 14 px for a second description line and its bottom, X axis and axis title up 14 px for a second source line, which grows upward. A title stays one line, cut at a word with `…`. The whole of each stays in `<title>`, `<desc>` and the accessible name. Text that fits is drawn as before. |
| `Kind` | `ChartKind`, `Line` | The chart type, and how X is laid out (by category or continuously). |
| `Theme` | `ChartTheme`, `Light` | `Light` or `Dark`, used when no `Style` is set. |
| `Style` | `ChartStyle?` | Colours, font and finish; wins over `Theme` and a cascaded style. |
| `Series` | `IReadOnlyList<ChartSeries>` | The data. At most 32 series, 100,000 points. |
| `XLabel`, `YLabel`, `Y2Label` | string | Axis titles. `Y2Label` names the right axis. On a gauge `YLabel` is the unit written after the score (`"%"`). |
| `XTicks` | `TickSource`, `Auto` | What labels a continuous X axis (0.33.0). `Auto`: the points' `Label`s replace the ticks when 1–24 labelled points stand in view, each cut to 12 characters — except on a time axis, which keeps its dates unless every label fits uncut, so long names stay in the tooltips. `Axis`: always the axis's own ticks. `PointLabels`: always the labels, at any count, thinned until no two touch; the axis's ticks only where no labelled point is in view. Blocks' labels never label the axis. Line, area, scatter, bubble, candlestick, OHLC, band, range and blocks charts; others refuse it set. |
| `Width`, `Height` | int, 900 × 420 | The SVG's viewBox, 320–4096 by 240–2160 (a sparkline from 60 by 16); the component scales it to its container, or with `FitWidth` draws it at the container's width. A strip (0.39.0) is drawn as tall as its content and does not use `Height`, which may be 16–2160; a bar chart with `FitHeight` (0.41.0) as tall as its rows, `Height` checked but unused. A heatmap with `CellWidth` (0.46.0) is drawn as wide as its columns make it and does not use `Width`. |
| `Sparkline` | bool | Draw the data alone, word-sized (0.34.0): no title, description or source written, no axes, ticks, gridlines or legend, zone bands and annotations without their labels — no `<text>` at all. The plot fills the drawing but for a padding just wide enough for its largest mark at any edge: a highlight's ring 6.5, `HighlightLast`'s 10, a hollow marker 5, a scatter dot 4.5, a filled or hovered marker 4, a line half its stroke, columns 0 (a drawing too small for that keeps 2 units of plot). The title stays the accessible name and `<title>`, the description the `<desc>`, and every point its focusable, named mark and native tooltip. Shown at its own width (`width:Wpx;max-width:100%`), not its container's. 60–4096 by 16–2160. Line, area, scatter and column charts, their series drawn as those marks; panes and `ValueLabels` refused. The component draws it without legend, toolbar, zoom or table. |
| `XAxis`, `YAxis`, `Y2Axis` | `AxisKind`, `Linear` | `Linear`, `Log`, or (X only) `Time` in Unix milliseconds. |
| `XFormat`, `YFormat`, `Y2Format` | `ValueFormat`, `Number` | `Duration` reads seconds; `Compact` writes 1.2k; `TimeOfDay` (0.27.0) reads seconds since a midnight as `HH:mm`, wrapping at 24 h, linear axes only; `Signed` (0.36.0) writes a number as `Number` does with its sign, `+5`, `−5` (a true minus, U+2212) and `0`, in ticks, names, value labels, annotations, the readout and the data table. None on a time axis. From 0.46.0 a heatmap takes `YFormat` (it writes its cells' values, their names, its colour-scale line and its HTML table in it) but not `Y2Format`, since it has no secondary axis; donut, radar and histogram charts still take none. |
| `YReversed`, `Y2Reversed` | bool | Smaller values higher (pace). Refused for kinds that draw from zero. |
| `YAxisSide` | `AxisSide`, `Left` | `Right` moves the main axis right; refused with a secondary series. |
| `YTickLabels` | `TickLabels`, `All` | `Ends` labels only the lowest and highest tick; `Bounds` (0.35.0) labels no tick, only the axis's two ends at their exact values in its format (with `IncludeZero`, `0` and the largest value); `None` (0.37.0) writes no label at all. In every pane that sets no `ChartPane.YTickLabels` of its own. Gridlines stay at every tick. |
| `YTickValues` | `IReadOnlyList<AxisTick>?` | Ticks of the main left axis set by hand (0.38.0), in place of those it would choose: a gridline exactly at each `AxisTick(Value, Label = null)`, labelled with its `Label` as given or else its value in the axis's format and `YUnit`, as `[new(0, "Front"), new(50, "Mid"), new(100, "Back")]`. A value outside the axis is left out, never stretching it, so set `YMin`/`YMax` to the range; `YTickLabels` still picks which labels are written; no minor gridlines on that axis. At most 24, no value twice, finite, positive on a log axis, labels at most 24 characters. Charts drawn on an X and a Y axis (the bar chart's along the bottom); donut, heatmap, radar, histogram, box, violin, gauge, ring, timeline, calendar and sparklines refuse it. `ChartPane.YTickValues` sets a pane's. |
| `YUnit` | string? | Up to 8 characters written straight after every value the main left axis writes (0.38.0), exactly as given (`"s"` → `+12.3s`, `" bpm"` → `152 bpm`): automatic ticks, bounds labels, mark names and tooltips, value labels, zone and annotation readings, the shared readout, the component's status line and data table. Not on a tick labelled by hand, not on the right-hand axis; CSV keeps raw numbers. A pane takes its own `ChartPane.YUnit`, not this. The kinds that take `YTickValues`, sparklines included, and from 0.46.0 heatmaps, which write it after their cells' values, their names, the colour-scale line and the table. `Axis.Unit` does the same for any `Axis`. |
| `XTickLabels` | `TickLabels`, `All` | Which X labels are written along the bottom (0.35.0): `All`; `Ends`, the first and last drawn, ticks or points' labels; or `Bounds`, only the axis's two ends at their exact values in its format, `XMin`/`XMax` or the data's ends, the first starting at the plot's left edge and the last ending at its right, never the points' labels. Gridlines stay. Line, area, scatter, bubble, candlestick, OHLC, band, range, blocks and timeline charts; others refuse it set, and `Bounds` is refused beside `XTicks = PointLabels`. `None` is refused: every pane reads its X from this axis. |
| `XMin`, `XMax`, `YMin`, `YMax`, `Y2Min`, `Y2Max` | double? | Explicit axis bounds. |
| `YMinSpan` | double? | The least the main plot's left axis spans, centred on its data (0.34.0): when the data's range is smaller, the axis runs from (min + max) / 2 − span / 2 to (min + max) / 2 + span / 2, so a 0.3 kg wobble on `YMinSpan = 8` reads as small; data wider than the span fits as before. A band's or range's bounds count as data; a secondary series does not. Positive; refused beside `YMin`/`YMax`, on a log axis, with `IncludeZero`, on kinds drawn from zero and when the axis carries columns or an area; line, scatter, bubble, band, range, candlestick, OHLC and blocks charts take it, reversed or not. `ChartPane.YMinSpan` sets a pane's. |
| `YSymmetric` | double? | Holds the main plot's left axis symmetric about zero (0.36.0): it runs from −m to +m, m the largest of this value and the data's distance from zero either way, so zero stays in the middle and form of +4 and −4 stand equally far from it. Positive; refused beside `YMin`, `YMax` or `YMinSpan`, on a log axis, and on kinds without such an axis (donut, heatmap, radar, histogram, box, violin, gauge, ring, timeline, calendar); allowed reversed and beside `IncludeZero`. A secondary series is not measured on it. `ChartPane.YSymmetric` sets a pane's. Pair it with `YFormat = ValueFormat.Signed`. |
| `IncludeZero` | bool | Force zero onto the value axis. |
| `TimeZone` | string? | IANA or Windows zone id for a time axis's calendar, e.g. `"Europe/London"`. |
| `SkipWeekends`, `TimeSkips` | bool, `IReadOnlyList<TimeSkip>` | Leave weekends or spans (`TimeAxis.Day(date)` for a holiday) out of a time axis. |
| `Annotations` | `IReadOnlyList<ChartAnnotation>` | Reference lines and bands behind the data, or over it with `InFront`. |
| `YZones` | `ZoneScale?` | Shades each zone as a band behind the main plot; on a calendar, colours each day by its zone. |
| `Panes` | `IReadOnlyList<ChartPane>` | Extra panes beneath the main plot, at most five (0.37.0; three before), so six plots; pane *k* is `Panes[k − 1]`. |
| `PaneTitles` | `PaneTitlePlacement`, `Axis` | `Above` (0.37.0) writes the main plot's `YLabel` and each pane's `Label` as one horizontal line over the plot's left edge, in the text colour, cut with `…` to the plot's width, its whole kept as its accessible name and tooltip (put the key fact first); the main plot moves down 18 and the gap between plots grows from 24 to 30. A right-hand title stays up the side. With no tick label written up the left (`TickLabels.None` everywhere) the left margin narrows from 76 to 30. Line, area, scatter, bubble, column, stacked column, band, range, candlestick, OHLC and blocks charts; others and sparklines refuse it. |
| `MinorGridlines` | bool | Lighter lines between labelled ticks. |
| `Bins` | int? | Histogram bin count; null chooses from the data. |
| `DensityCells` | int? | Scatter only: aggregate into shaded cells (8–200 across). |
| `MaxRenderedPoints` | int, 1200 | Line and area sampling budget per continuous run, 16–5000. From 0.37.0 a run longer than it is thinned over `XMin`–`XMax` only, with the nearest point outside each side, so a zoomed view draws more detail; a run within it is drawn whole. |
| `Sampling` | `SamplingMethod`, `MinMax` | `MinMax` keeps each bucket's lowest and highest point. `Average` (0.37.0) cuts the X range shown into `MaxRenderedPoints` equal slices, the same for every series, and draws each run's points in a slice as one point at their mean X and Y, the mean rounded to the series' own precision (at most two places), named `, average of N points` and reporting the slice's first point; the shared readout says `average of 12 s` once in each column's label and reads entries plainly; applies to series drawn as lines or areas whose points in view outnumber the budget. A highlighted point, and a `HighlightLast` point, keeps its own mark beside the average. Bands, trends and other marks keep `MinMax`. |
| `GaugeSweep` | double, 270 | Gauge only (0.26.0): how far round the arc runs, 180 (semicircle) to 360 (full circle), centred at the top. Any other kind refuses a value but 270. |
| `TimelineConnectors` | bool, true | Timeline only (0.27.0): join a span to the span in another lane that starts exactly where it ends with a thin vertical line, as a hypnogram does. `false` draws a plain state chart; every other kind refuses `false`. |
| `CalendarLayout` | `CalendarLayout`, `Weeks` | Calendar only (0.28.0): `Weeks` is the contribution grid, a column per week and a row per weekday, months named above; `Months` is a small grid per month, set left to right and wrapping. Other kinds refuse it set. |
| `CalendarCell` | `CalendarCell`, `Square` | Calendar only (0.28.0): each day as a rounded `Square` (corners `BarRadius` or 3 px), a `Dot`, or a `Bubble` whose area is proportional to its value, the largest filling its cell. Other kinds refuse it set. |
| `SharedReadout` | bool | The component alone (0.36.0): one vertical guide through every pane at the X nearest the pointer, a tap or the focused point, a ring round each shown series' point there, and one tooltip reading the X and then each series' name and value in legend order, with its `ValueNote`, zone and change words, `Form −8.7, worse than the previous`; a missing value reads `missing`. A series is read where it has a point within half the closest spacing of the X values; blocks by the X they cover. The arrow keys then step by X (Left/Right, Home/End, Page Up/Down ten), Up/Down move between the series there, Escape hides it, and the status line reads `3 Jun 2026 · Fitness 52.3 · …`. Never in the SVG or the gradient hash: `ChartSvg.Render` draws the same chart with it or without. Line, area, scatter, bubble, band, range, candlestick, OHLC and blocks charts; a sparkline and the other kinds refuse it. `ChartSvg.Readout(spec)` returns the same table (`ChartReadout` → `ReadoutColumn` → `ReadoutEntry`, positions in viewBox units) for a host that draws its own. |
| `WeekStart` | `DayOfWeek`, `Monday` | Calendar only (0.28.0): the day each week starts on, ISO's Monday unless set. Other kinds refuse it set. |
| `BarTrack` | bool | Bar and column charts (0.39.0): a track behind each bar from zero to `YMax` in the style's `Grid` colour, rounded as the bar is, outside the bar's mark, as a meter is drawn. Needs `YMax`, an axis from zero (`YMin` unset or 0, no value below zero) and no secondary series; stacked columns and other kinds refuse it. A value above `YMax` is drawn at the track's end and named `…, above the scale, drawn at 100`. On a horizontal bar chart a bar on a track is at most 18 units thick, centred in its row; its `ValueLabels` stand 6 past the track's end and the right margin grows to hold them; the left margin fits the widest category name (generous 12 px estimate + 24, + 18 more with an `XLabel`), capped at 45 % of the width, a longer name cut with `…`; with `YTickLabels = None` and no `YLabel` the bottom margin is 24 (36 above a source). On columns the label stands above the track's top. `YTickValues = []` leaves out the gridlines across the tracks. Tracks stand over zone bands and references behind the data; draw a target `InFront`. |
| `DrawTitles` | bool, true | Off (0.39.0): neither `Title` nor `Description` is drawn and the body moves up 50 units (a plot from 28 rather than 78); both stay the `<title>`, `<desc>` and accessible name. Every chart kind; graphs always draw their title. Not `Render`'s `includeTitles`, which only writes or leaves out each mark's native tooltip. |
| `PaintBackground` | bool, true | Off (0.41.0): the root `<svg>` writes no `background` (it carries the colour as `--lumen-ground` instead) and no shape fills the drawing, so the card or panel it sits on shows through; nothing else moves. Lumen still checks contrast against `Style.Background` and draws its halos and separators in it (value-label and end-label halos, `InFront` references, hollow markers, a highlight's outline, a gauge's knob and target), so **set `Style.Background` to the surface's colour** when leaving it unpainted. The SVG export has no background either, and the component's PNG export is transparent there. Every kind; `GraphSpec.PaintBackground` does the same for graphs. |
| `FitHeight` | bool | Horizontal bar charts only (0.41.0): drawn as tall as their rows need instead of `Height`: 36 units a category on tracks, 32 without, 38 when any category has a `SubLabel`; plus 78 above the rows for title and description (+14 for a two-line description, 28 in all with `DrawTitles = false`), 76 under them for value ticks and title or 24 where neither is written (`YTickLabels = None`, no `YLabel`; 36 above a `Source`, +14 for a second source line), and 22 a legend row when `Render` includes the legend. Three tracked meters without titles, ticks or source: 28 + 108 + 24 = 160. No 240 floor; `Height` is still validated (240–2160) but unused. The component honours it (`FitWidth` unchanged); hiding the only series in a category drops its row. Other kinds refuse it. |
| `CellText` | bool | Heatmaps only (0.46.0): write each cell's value (in `YFormat` and `YUnit`) on one line, 11 px at weight 600, and under it the point's `SubLabel`, 10 px, both centred in the cell. Each cell's words are in whichever of `Style.Text` and `Style.Background` contrasts more with the cell where that reaches 4.5:1, else in black or white, whichever contrasts more (one of them always reaches 4.58:1), so every rated cell writes its value; a not-rated cell writes its value, or `—`, and its sub-label in `Style.Text`. A sub-label that does not fit the cell's width less 6, or the two lines its height less 4 (a row needs 29), is dropped first, then the value if it does not fit alone; the cell's name always says both. `ValueNote` is never drawn in a cell. Refused on every other kind. |
| `CellWidth` | double? | Heatmaps only (0.46.0): the width of each column in pixels, at least 24 and finite. The drawing is then 165 + columns × `CellWidth` wide, rounded up and never narrower than 320 (the room left over at its right), and `Width` is not used; a drawing wider than 4096 is refused, saying how many columns and pixels it makes. Column labels are then thinned so that no two overlap, 6 units apart at 12 px, in place of the fixed "every n-th past 12 columns" (without `CellWidth` the labels are as they were). In `<LumenChart>` such a heatmap is shown at exactly its drawn size, with or without `FitWidth`. Null by default; refused on every other kind. |

## ChartSeries

`new ChartSeries(string Name, IReadOnlyList<ChartPoint> Points, string? Color = null)`, plus init properties:

| Member | Meaning |
|---|---|
| `Secondary` | Measure on the right-hand axis. At least one series per pane stays on the left. |
| `Kind` | Override this series' mark: `Line`, `Area`, `Column`, `Scatter`, `Band`, `Range` (0.27.0) or `Blocks` (0.29.0). Allowed on line, area, scatter, bubble, band, range, blocks, column, candlestick and OHLC charts; blocks are refused on a column chart. |
| `Pane` | 0 is the main plot; *k* needs `ChartSpec.Panes[k − 1]`. |
| `Trend` | Draw a trend (line, area, scatter, bubble marks): a least-squares line across the plot unless `TrendFit` says otherwise. Dashed in the series colour, named for assistive technology. |
| `TrendFit` | `TrendFit.Linear` (default), `MovingAverage`, `Polynomial` or `Exponential` (0.32.0). All are fitted in the space the chart draws, so on a log Y axis a moving average is the geometric mean and an exponential is straight. A polynomial or an exponential is drawn only across the X its observations cover (an exponential's positive ones), named `Load trend: quadratic fit, R squared 0.93` or `… exponential fit, rising, R squared 0.88` (R² on the logarithms, as Excel reports it); a moving average is drawn at the last point of each trailing window, named `HRV trend: 7-point moving average`. Refused without `Trend = true`. |
| `TrendPoints` | A moving average's window, 2–1000 points, 7 by default (0.32.0). A missing value holds its slot and adds nothing; the line breaks where fewer than half the window (rounded up) is present. Points must be in X order. Refused set on any other fit. |
| `TrendDegree` | A polynomial's degree, 2 (quadratic, default), 3 (cubic) or 4 (quartic) (0.32.0). Refused set on any other fit. |
| `ProjectedFrom` | Dash a line or area from this X onward (planned values). |
| `Zones` | Colour the series by the zone each value falls in (`ZoneScale`): lines, areas, scatter points, bubbles, columns, bars and blocks. |
| `Summary` | A precomputed `BoxSummary` for a box chart (then `Points` must be empty). |
| `StrokeWidth` | 0.5–12 px for line, area and band strokes. |
| `Curve` | `LineCurve.Linear`, `Smooth` (monotone, never overshoots), `Step`. |
| `Fill` | `AreaFill.Flat` or `Fade` (vertical gradient) on areas and columns. |
| `Gradient` | `IReadOnlyList<ColorStop>` — colour a stroke continuously by value; not with `Zones`. On a gauge it colours the arc along its length; not with `YZones`. From 0.40.0 it also fills columns (a column chart or a column series) and a bar chart's bars: one `userSpaceOnUse` gradient along the value axis, up for columns and across for bars, each stop at its value, so each column takes the colour of the value at each height and a taller one reaches further; past the ends the stop colours carry on. A point's `Color` still fills flat; value labels stay in the text colour; the legend key shows up to four stop colours. Refused on stacked columns, beside a faded `Fill`, with `Zones`. Pick stops that each clear 3:1 on the background. |
| `Markers` | `MarkerStyle.Auto` (hover/focus in the refined finish), `None`, `Hollow`, `Filled`. |
| `HighlightLast` | Ring the latest point of a line or area. |
| `ValueLabels` | Print each column's or bar's value past its end when it fits, in the text colour. From 0.33.0 also each line or scatter point's value, 4 px above its marker, in the point's colour (its change colour where it has one, a gradient's colour at its value) where that colour clears 4.5:1 against the background, else the style's `Text` colour, at 11 px weight 600, its `ValueNote` after it muted at normal weight, over a 3 px halo in the background colour. It moves in from the plot's left and right edges so it is never cut, goes 4 px below the marker where above would leave the plot or meet a value label already written (columns' included), and is left out with room in neither place; the value stays in the mark's name. Area, band, bubble and stacked series refuse it. |
| `ChangeColors` | `ChangeColors.None` (default), `HigherIsBetter` or `LowerIsBetter` (0.33.0): colour each point of a line or scatter series by how it changed from the nearest earlier point with a value — the style's `Rising` colour when better, `Falling` when worse, the series colour when level or first. Better follows the setting, not the screen, so it holds on a reversed axis and on a shared scale. The marker and the segment arriving at the point take the colour (a point's `Color` colours the segment leaving it); a gap draws no segment, but the point after it compares with the last value before it. Each mark's name and tooltip add `, better than the previous`, `, worse than the previous` or `, level with the previous`; the first adds nothing. Refused on other marks, beside `Zones`, a `Gradient` or point colours, on scatter points out of X order and on a density scatter. |
| `EndLabel`, `EndNote` | Name a line, area or scatter series at its end instead of in a legend (0.38.0), each ≤ 24 characters: the label just right of the last point drawn in view (a scatter series' point furthest along X), centred on it, 12 px weight 600 in the series colour where it clears 4.5:1, else the text colour; the note after it on the same line in the muted colour (the text colour where muted falls short). Over a halo of the background. The right margin grows to the widest, capped so the plot keeps half the drawing's width (≈ 10 characters at 340 — use short names); past the cap the note is cut with `…` first, then left out, and only then the label (0.40.0), the whole kept as `<title>` and `aria-label`. Labels whose spans overlap never overlap: sorted by height and moved apart as little as possible, 14 units a line (12 if tight), within the plot ± 8; one moved > 3 units steps 6 right and gets a 1-unit connector in its colour (muted under 3:1); past what fits the lowest are left out. The last point's name gains `, labelled You · leader`. Refused on other marks, a density scatter, beside a secondary series or `YAxisSide = Right`, on a sparkline; a note needs a label. With every series labelled use `includeLegend: false` / `ShowLegend="false"`. |
| `AverageOf` | `string?` (0.41.0): says the series' points are already averages the app made, and over what, `"12 s"` or `"a week"`, ≤ 16 characters on one line. Each mark with a value is named, and its tooltip read, with `, average of 12 s` after its value's words (`Power: 1:00:06, 266, average of 12 s`); the shared readout says it once in the column's label, `1:00:06 · average of 12 s`, when every entry there has the same `AverageOf` and none is Lumen's own average, entries then reading plainly, and otherwise after each such entry's value (`Power 266, average of 12 s`); the component's status line reads the same. A mark Lumen averaged under `SamplingMethod.Average` keeps Lumen's words (`, average of 4 points`, the column's slice). Missing values say nothing; CSV and the data table keep the values; no drawing changes. Lines, areas, scatter, bubbles, columns, bars, stacked columns, bands, blocks, heatmap and radar series (sparklines too); candles, range bars, histograms, boxes, violins, timelines, calendars, donuts, gauges, rings and strips refuse it, as do blank, longer or multi-line values. |
| `Goal` | Ring charts only (0.26.0): the ring's target, `double?`, positive, 100 when null; progress is `Y / Goal`. The point's `Label` is the unit (`"kcal"`). |

`ChartSeries.From<T>(name, items, x: item => …, y: item => …, label: item => …)` maps your own objects.

## ChartPoint

`new ChartPoint(double X, double? Y, string? Label = null, double Size = 1)` — `Size` is bubble area. Init properties: `Open`, `High`, `Low`, `Close`, `Color` (this mark's colour; beats zone and series colour), `XEnd` (0.27.0, timelines and, from 0.29.0, blocks only: where a span or block ends, above `X`; Unix milliseconds on a time axis), and `Highlight` (0.34.0: a `#RRGGBB` colour that rings this point of a line or scatter series with an enlarged marker, radius 5.5, outlined 2 px in the background colour, whatever the series' `Markers` and in sparklines and full charts alike; the line keeps its colour and course, sampling keeps the point, and `HighlightLast`'s ring takes the colour. Pair it with a `ValueNote` such as `" · PB"`, so the tooltip and accessible name say why the point is ringed — the colour is never the only cue. Refused on areas and every other mark, on a density scatter, and in any other colour form), `SubLabel` (0.40.0: a second line under the point's category name on column, stacked column and bar charts, ≤ 16 characters, one line, 11 px muted; columns get it 14 under the name, cut past 12 characters, the plot giving up 14 at its foot only when one is set, and are then thinned by the room their words take — at 340 four columns keep `152 bpm`, about eight a bare number; bars write the name half a line up and the sub-label half a line under the bar's centre. A category takes the first sub-label any series gives it, and different ones for one category are refused; each mark's name and tooltip say it after the name, `Heart rate: L3 · 168 bpm, 168`, as do the component's status line and table. From 0.46.0 a heatmap's cells take one too, each its own (`/12 starts` and `/4 starts` may stand in one column; the rule that a category has one sub-label does not apply to heatmaps), written as the cell's second line when `CellText` is set and always said in its name, `Sprint: 2025 · /12 starts, 2.8`, in the same order a column chart's is. Refused on other kinds, a sparkline, blank, longer or multi-line), `GapLabel` (0.42.0: the word a missing value is written as, such as `"absent"` for a round a rider was entered in and missed, 1–12 characters on one line, on a point whose `Y` is `null` in a line, area or scatter series. The line still breaks there; the word is written at the point's X, centred and moved in from the plot's sides, just inside the plot beside the start of the value axis — above the bottom edge, or below the top edge on a reversed axis — 11 px, weight 600, on a halo of the background colour, in the point's `Color` where that clears 4.5:1 on the background, else the series colour where that does, else the text colour. It keeps clear of the value and gap labels written before it and is left out where it has no room (two missed rounds side by side at 340 write the first word only). The point becomes a focusable mark, named and tooltipped `Share: Round 3, absent` — the word in place of `missing`, then any `ValueNote` — that the arrow keys reach; the shared readout reads it `Share absent`, even at an X where no series has a value, and the status line and data table say it; CSV leaves the value empty. A round that was not held is no point at all, so the line joins over it. Refused on a point with a value, other kinds, a density scatter, a sparkline, blank, longer or multi-line), and `ValueNote` (0.33.0: at most 20 characters written straight after the value — include any space yourself — such as `"/48"` for a field size or `" inside baseline"` for a status: muted after a value label, and after the value in the mark's tooltip and accessible name, `Position: 16-05-2026, 24/48, better than the previous`, the component's data table and status line, and a CSV `Note` column. A missing value has none in its name unless it has a `GapLabel`, which the note then follows; the CSV keeps it. Refused on candles, range bars, histograms, boxes, violins, timelines, calendars, gauges and rings; on a heatmap the note follows the value in the cell's name and the grid table, as written and never in the cell itself), and `NotRated` (0.46.0: on a heatmap cell, why it is not rated, such as `"too few starts to rate"`, 1–24 characters on one line, no control characters. The cell is drawn unshaded, in the background colour, with a dashed outline (`stroke-dasharray='3 2'`) in `Muted` at full opacity; its value, if any, is left out of the colour scale's lowest and highest; with `CellText` it writes its value or `—`, and its sub-label, in the text colour; and its name ends `, not rated: {reason}`, `Long distance: 2025 · /4 starts, 1.2, not rated: too few starts to rate`, without a value where it has none. A not-rated cell with a `null` `Y` is still drawn and focusable; a `null` `Y` without `NotRated` still draws no cell. Left out of the gradient-ID hash when null. The CSV gains a `NotRated` column when any point sets it. Refused on every other kind, blank, longer than 24 characters or with a line break).

Factories: `ChartPoint.Candle(x, open, high, low, close, label?)`; `ChartPoint.Interval(x, y, low, high, label?)` for band and range points (`y` may be `null`; on a range it is the dot, and must lie between `low` and `high`); `ChartPoint.Span(start, end, label?)` (0.27.0) for a timeline span, with no `Y`; `ChartPoint.Block(start, end, height, label?)` (0.29.0) for a block from `start` to `end` rising to `height`; `ChartPoint.Observation(value)` for histogram, box and violin input.

## ChartAnnotation

`new ChartAnnotation(AnnotationAxis Axis, double From)` with `To` (makes it a band), `Label`, `Color`, `Dashed` (default true), `ShowValue` (default true) and `InFront` (default false), both 0.35.0. A gauge (its target is drawn over the score already) and a calendar refuse it. `AnnotationAxis.Y` is the value axis wherever the chart draws it; `X` is refused on category charts. Time-axis annotations take Unix milliseconds.

## Rendering and export

- `ChartSvg.Render(spec, includeLegend = true, includeTitles = true)` → SVG string. Throws `ArgumentException` for an invalid spec. `includeLegend` adds the series legend under the chart (kinds with a key of their own — donut, heatmap, box, violin, gauge, calendar, strip — leave it out); `includeTitles` writes or leaves out only the native tooltip, the `<title>`, in each mark: the chart's title and description are always its `<title>`, `<desc>` and accessible name, and are drawn unless `DrawTitles` is off.
- `ChartSvg.PartLabel(spec, index)` (0.39.0) → what a strip's part says, `Easy: 24%, 12:20`, as its mark is named; from 0.40.0 an amount that writes exactly as its share is said once, `Moderate: 30%`.
- `ChartSvg.ResolveStyle(spec)`, `ChartSvg.SeriesColor(series, index, style)`, `ChartSvg.LegendKey(spec, index)` (a series' legend key as a small SVG) and `ChartSvg.LegendLabel(spec, index)` (what the legend writes: the name, and on a ring `Move: 540 of 600 kcal`, on a gauge `Recovery: 72 %`, on a timeline `REM 1:42, 22 %`).
- `ChartExport.Csv(spec)` → CSV of the original observations (time charts add an ISO `XTime` column, band and range series `Low,High`, ring charts a `Goal` column, timelines and blocks an `XEnd` column, a chart with any `ValueNote` a `Note` column (0.33.0), and a chart with any `NotRated` point a `NotRated` column, the last of all, holding each cell's reason and empty for a rated one (0.46.0); a calendar writes each original point, not each day's total).
- `ChartExport.HtmlTable(spec)` (0.46.0) → a heatmap as an HTML grid table, for a static page or a screen reader; any other kind throws `ArgumentException`, and a spec that is not valid is refused first with its reason. It returns `<table class='lumen-grid-table'><caption>{title}</caption><thead><tr><td></td>` and a `<th scope='col'>` for each column, then a row for each series with `<th scope='row'>{series name}</th>` and a `<td>` for each column, in single-quoted attributes with every word HTML-encoded (so `·` is `&#183;`). The columns are every X the series have, in order, each labelled by the first label a point there gives it, whole (the drawing cuts a label at 10 characters and a row name at 17), or its X. A cell holds its value in `YFormat` and `YUnit` followed by its `ValueNote` as written, then ` · ` and its `SubLabel`, then `, not rated: ` and its reason, `1.2 · /4 starts, not rated: too few starts to rate`; a not-rated cell without a value holds `—`; a cell with no point, or neither a value nor a reason, is empty. A heatmap with no series is a table without rows, not a refusal. The table is bare: styled by `lumen.css` (`.lumen-grid-table`), which is in the Blazor package. For a static page wrap it in `<div class="lumen-table" tabindex="0" role="region" aria-label="Chart data">`, the region `<LumenChart>`'s "View data" uses, which `lumen.css` gives its scroll box (320 px tall) and focus ring, so a keyboard can scroll a table that does not fit. There is no HTTP endpoint for it.

A strip (`ChartKind.Strip`, 0.39.0) takes one series whose points are the parts of a whole in order: each point's `Label` names its part (required) and its `Y`, zero or more, is its amount; X is only order. One bar 18 units thick runs the width less 24 each side, each part as long as its share, in its `Color` or the style's series colours in order, parted from the next by a 2-unit gap in the background colour, its outer ends rounded by `BarRadius` or 6 (clamped to 9); a part of zero draws nothing, a sliver keeps 1 unit. Under it a key of 10-unit swatches and `Easy 24%` in the text colour, whole percentages adding up to exactly 100 (largest remainder, ties to the later part: thirds read 33, 33, 34), flowing and wrapping in rows 20 apart; a part of zero keeps its entry. Each part drawn is a focusable mark named `Easy: 24%, 12:20` (amount in `YFormat` and `YUnit`, then its `ValueNote`; from 0.40.0 an amount that writes exactly as its share, `30%` with `YUnit = "%"`, is left out: `Moderate: 30%`); Left and Right step parts. The share is of the strip's total, rounded to whole percentages adding up to 100: pass raw amounts (seconds), not shares already rounded, which are shared out again over their total and can differ from the amounts by a point (`Hard: 34%, 33%`). Drawn as tall as its content: bar at 64 (14 with `DrawTitles = false`), 16 under the last key row, plus a source line; `Height` unused. No series legend from `Render`, no toggle legend in the component. Refused: several series, panes, a missing/negative/NaN amount, a blank label, all zeros, more than 24 parts, annotations, `YZones`, value labels, a series' kind, secondary, trend, zones, gradient, change colours or end label, and axis settings (time/log/reversed axes, bounds, `IncludeZero`, `YAxisSide`, tick labels or values, minor gridlines, `XFormat`).

A calendar (`ChartKind.Calendar`, 0.28.0) takes one series on a time X axis. A point counts for the day its `X` falls on in `TimeZone`, and one day's points add up; a zero or null total is a rest day, drawn as an empty cell that takes no focus. Days run from the earliest point to the latest, or from `XMin` to `XMax`. Each day with activity is a focusable mark named `Tue 15 Sep 2026: 54, Moderate` (date, its points' labels, total in `YFormat`, zone); `PointSelected` reports the day's first point. With `YZones` a day takes its zone's colour; without, a ramp across the active days from a third of the way between the empty cell's `Grid` colour and `HeatmapHigh` up to `HeatmapHigh` (0.30.0; it does not use `HeatmapLow`), so the quietest day stands apart from a rest day on light and dark styles alike. An X annotation outlines its day and joins the key under the grid. Values must be nonnegative; `YMin`/`YMax` are refused, so the ramp cannot be pinned across charts.
Blocks (`ChartKind.Blocks`, or a series' `Kind = ChartKind.Blocks` on a continuous chart, 0.29.0) draw each point made with `ChartPoint.Block(start, end, height, label?)` as a block exactly from `X` to `XEnd`, standing on the bottom edge of its plot (its pane's, on its series' own axis, left or right) and rising to `Y`. `IncludeZero = true` raises them from zero; otherwise an axis fitted to the data reaches below the lowest block — the slowest, on a reversed axis — until it stands a sixth of the plot, unless that end's bound is set. Blocks of one series that touch are parted by a 1-pixel hairline, half from each (a quarter of the width of a block under 2 pixels); the far end is rounded by `BarRadius`, or 4 pixels, at most 6; a block whose value stands above the bottom of its axis is at least 2 pixels tall (0.35.0), so a count of one among hundreds still shows, while one at the bottom, a count of zero, draws nothing visible and stays a named, focusable mark; colour is the point's `Color`, else its zone in the series' `Zones`, else the series colour. They draw in the column layer, under lines and points. Each is a focusable mark named `Lap 2: 1 to 2, 4:52` or `Interval 2: 10:00 to 14:00, 275, Lactate threshold` (label, span in `XFormat`, height in the axis's format, zone), led by its series' name when it has no label or several series draw blocks. Refused: overlap within a series, a missing `XEnd` or `Y`, a log X axis, column charts, `Trend`, `ProjectedFrom`.

A heatmap (`ChartKind.Heatmap`, extended in 0.46.0 into a table of results) draws a row for each series and a column for each distinct X, and a cell for each point with a value, shaded on a ramp from the style's `HeatmapLow` to `HeatmapHigh` between the lowest and highest rated value; row names are cut at 17 characters and column labels at 10. Each cell is a focusable mark named as a column chart's is, `{row}: {column} · {sub-label}, {value}{ValueNote}`, with `, not rated: {reason}` after a not-rated cell, and the value in `YFormat` and `YUnit`; a point's `Low` and `High`, which a heatmap does not draw, are not said. The options are all off by default: `CellText` writes the words in the cells, `ChartPoint.SubLabel` is the second line (each cell's own), `ChartPoint.NotRated` marks a cell that is no result, and `CellWidth` sets the columns' width so the drawing scrolls instead of squeezing. The colour-scale line under the grid reads `Color scale: 1.7 low to 3.5 high` in the refined finish, in `YFormat` and `YUnit`: if it would run past the drawing's right edge (at the 12 px it is drawn in) the `Color scale: ` prefix is dropped, and if it is still too wide it is cut with `…`; with no rated cell it reads `Color scale: no rated cells`. The classic finish keeps `Color scale: 1.7 (light) to 3.5 (dark)`, exactly as 0.23.0 wrote it. Refused: `CellText`, `CellWidth` or `NotRated` on any other kind; a `CellWidth` below 24, not finite, or making the drawing wider than 4096 (`At 40 pixels a column, 100 columns make a drawing 4165 pixels wide, past the 4096 a chart may be; narrow the cells or show fewer columns.`); a `NotRated` that is blank, longer than 24 characters or has a line break; `Y2Format` (`A heatmap has no secondary axis, so it takes no Y2 format; its cells' values take YFormat.`); and, as before, `YTickValues`, tick labels, annotations and the other axis settings it has no axis for. The component's "View data" for a heatmap is `HtmlTable`'s grid in place of the flat list (rows the reader has hidden in the legend left out, no 500-row cap), and its CSV and the HTTP API's `/api/charts/svg` and `/csv` take `cellText`, `cellWidth` and `notRated` in the JSON.
- `ChartValidation.Validate(spec)` validates without rendering.

## Graphs

`GraphSpec { Title, Nodes = [new GraphNode(id, label, color?)], Edges = [new GraphEdge(source, target, label?)], Layout = GraphLayout.Layered or Circular, Direction, Theme, Style, Width, Height, PaintBackground }` (`PaintBackground = false`, 0.41.0, leaves the root unpainted as a chart's does). `GraphEngine.Render(graph, positions?)` → SVG; `GraphEngine.Layout(graph)`, `Routes(graph)`, `Crossings(graph)`. `Direction = GraphDirection.TopToBottom` (0.30.0) puts a layered graph's levels in rows down the drawing, each level spread across the width, arrows pointing down; edges leave from under a node's label, edge labels stand beside their edge and a self-loop at its node's right. Circular graphs ignore it. `GraphEngine.Fit(graph, width)` returns the graph as it should be drawn in a box that wide (clamped 320–4096): unchanged when it fits; a layered graph turns top to bottom when its levels would stand closer than its widest label (cut to 22 characters) plus 16 px, or 70 px, and grows 110 px a level up to 2160; a level too full for the width even then takes the narrowest width that holds it; a circular graph grows taller instead, and widens where two nodes at one height cannot stand their labels 16 px apart. Never shorter than its own `Height`.

In every layout (0.31.0) an edge whose straight run from a node would cross that node's label meets the node at the foot of the label, 50 px below its centre, instead of running through the words; an edge's label takes the first place along its edge, from the middle outwards, above then below it (top to bottom: right then left), that keeps off every node, node label and earlier edge label, and otherwise stands at the middle as before. A circle stands in from the sides by half its widest label (or a node's radius) plus 24 px. An edge can still cross another node's label in a crowded graph, and an edge label can sit on another edge's line.

| `Placing(int? Place)` | One event's result. `Place` is the finishing place, 1 for first; a null, 0 or negative place leaves the result (and its points) out of the chart. Plus `Field` (`int?`, written after the place as `/48` when above 0), `Points` (`double?`; null is never a zero: a gap in the points line of a series that scores at other events, no mark in one that never scores), `Date` (`DateOnly?`; when every result has one the events are drawn in date order, and it labels the event), `Label` (`string?`; wins over `Date`; a blank or whitespace label counts as missing) and `Series` (`string?`; the league or cup the event belongs to; surrounding spaces ignored, null or blank a series of its own). |
| `PlacingsOptions` | `PlaceName` ("Place": the places line's name, and the start of each line's name when there are several series), `PointsName` ("Points": the points line's name and its pane's label), `DateFormat` ("d MMM yyyy", invariant culture), `Unlabelled` ("#{0}", the label of an event with neither a label nor a date; `{0}` is its number from 1 in the drawn order), `PlaceColors` (`IReadOnlyList<string>?`: the places lines' colours used in turn and cycled; null takes the style's series colours in order without any within 60 sRGB distance of its `Rising` or `Falling` colour (all of them if none would be left), line `k` the filtered `[k % n]`), `PointsColor` (null takes the next filtered colour after the places lines, `[lines % n]`) and `Style` (null is `ChartStyle.Light`). The title, description, `YLabel`, width and height are not options. |

One line per series, named `PlaceName` (one series) or `PlaceName · Series`, each with `ChangeColors.LowerIsBetter`, value labels and filled markers, holding points only at its own events and so drawn joined across the others'; with several series the one for results with no series keeps plain `PlaceName`; each place's note is `/field`. `XTicks` is `TickSource.PointLabels`, so more than 24 events keep their labels, thinned. The points are one line named `PointsName` in a pane labelled `PointsName`: a point at each event that has points, a gap (null Y) at an event without points whose series scores elsewhere, and no point at an event of a series that never scores, so the line joins across it; no points, no line and no pane. ## Blazor components (`Lumen.Charts.Blazor`)

- `<LumenChart Spec="…" PointSelected="(PointSelection p) => …" />` — `PointSelection(SeriesIndex, PointIndex)`.
- Keys (0.36.0): every chart has one roving point stop, and from 0.42.0 that is its only tab stop while its drawing fits its box: the script takes the viewport's `tabindex` (to −1), its `role=region` and its `aria-label` away then, and gives them back while the drawing scrolls (a chart without `FitWidth` below 640 px), so the chart has two stops, the viewport first, only then; the prerendered markup still writes the viewport as a region and a stop, which a page without the script keeps — its script leaves one mark at `tabindex=0` (the first point of the first series, then the last one focused) and the rest at −1, while the static SVG keeps every mark at 0. Left/Right move along a series, skipping gaps (a gap with a `GapLabel` is a mark they stop on); Up/Down to the nearest point at that X in the series before or after (then the chart's references and other aggregates); Home/End to its ends; Page Up/Down ten points; Enter/Space select; Escape hides the tooltip. The keys are named in hidden words that the script makes the viewport's `aria-describedby` while it scrolls, and the drawing's otherwise (always a sparkline's). `LumenGraph`'s arrow keys still move a node. With `SharedReadout` the keys step the readout by X instead. Test the keys with real input (Playwright's `keyboard.press`): a `KeyboardEvent` dispatched from script can move focus without bringing up the readout.
- Drag to zoom (0.37.0): on a chart with zoom, a mouse or pen pressed on the plots and dragged 8 px or more draws a translucent band through every pane, and letting go zooms to its X (no narrower than 1 % of the whole); Escape lets it go, a shorter drag is a click, and a touch keeps the tap readout. Reset view restores. `ChartSvg.Plot(spec)` returns a `ChartPlot(Left, Right, Top, Bottom, X)`: where the X axis's ends and the plots' top and bottom stand in the drawing's units, and the `Axis` to `Map` and `Invert` with them, or null for a chart without a continuous X axis.
- `ShowLegend` and `ShowToolbar` (0.38.0), both `true` by default (the markup is then as before). `ShowLegend="false"` leaves out the legend of toggle buttons, for a chart whose series are named in the drawing (end labels, pane headers); the reader can no longer hide a series. `ShowToolbar="false"` leaves out zoom, pan, reset, the exports and View data, for a phone card, but keeps the `role=status` line, visually hidden (`lumen-quiet`), so a screen reader still hears the readout and the point chosen; drag to zoom and the arrow keys still work. It takes away the keyboard's zoom and the only way to the data table, so keep it where those matter.
- A large spec on an `InteractiveServer` island travels in SignalR's circuit-start message: six channels × 600 points went past the default 32 KB `MaximumReceiveMessageSize` and the circuit closed with only a console error, leaving a static chart. Raise it, `AddInteractiveServerComponents().AddHubOptions(o => o.MaximumReceiveMessageSize = 256 * 1024)`, or let the island load its own data.
- `<LumenChart Spec="…" FitWidth="true" />` (0.25.0 and later) draws the chart at the width of its container instead of `Spec.Width`: measured once the component is interactive and again when the container settles at a new width, in whole pixels, never below 320 (60 for a sparkline). It lifts the stylesheet's 640 px minimum for that chart alone (a `lumen-fit` class on its root), keeps zoom, hidden series and point selection across a redraw, and exports SVG and PNG at the fitted width. Prerendered and static charts are drawn at `Spec.Width` and scaled until then. Default `false`, which renders as before. A heatmap with `CellWidth` (0.46.0) is the exception: it is shown at exactly its drawn size whether `FitWidth` is set or not, before the box is measured and after, so the component marks its root `lumen-fixed` and its viewport carries `--lumen-drawn:{width}px`, which the stylesheet holds the drawing's minimum and maximum width to; a narrower box scrolls it sideways and a wider one leaves room beside it, and it is never squeezed or stretched. Every other chart's markup is as it was.
- The data table (0.46.0): "View data" opens a table in a `<div class="lumen-table" tabindex="0" role="region" aria-label="Chart data">`, a focusable named region with a focus outline, so a keyboard can scroll a table taller than its 320 px box (axe's `scrollable-region-focusable`); this holds for every kind. For a heatmap the table is `ChartExport.HtmlTable`'s grid of the rows the reader has not hidden, with row and column headers, in place of the flat Series, X / Category and Value list; every other kind keeps its list.
- A sparkline (`Spec.Sparkline = true`, 0.34.0) renders as its drawing alone in a root marked `lumen-chart lumen-spark`: no legend, toolbar, zoom, data table or scrolling region, its marks' tooltips the only chrome. A tooltip stands just above the drawing, as wide as its words (at most 280 px) and kept 16 px inside the page, rather than over the line. Point selection and `PointSelected` work as on a chart.
- `<LumenGraph Spec="…" NodeSelected="(string id) => …" />` — draggable nodes in an interactive render mode. `FitWidth="true"` (0.30.0 and later) draws it as `GraphEngine.Fit` lays it out for its container's width, so a phone shows a deep layered graph top to bottom instead of scrolling sideways; dragged nodes keep their place in proportion and return to the layout when it turns.
- `<LumenPlanner Spec="…" View="…" ViewChanged="…" EventSelected="(PlannerEvent e) => …" DaySelected="(DateOnly day) => …" ShowFilters="true" />` (0.44.0) — the interactive season planner, needing an interactive render mode (prerendered it draws the year with its toolbar and chips). `Spec` (required) is the `PlannerSpec`; its `Filter` is where the reader starts and its `Width` is used only until the box is measured. `View` is a `PlannerView`, `PlannerView.WholePeriod` by default, bound with `@bind-View`; `ViewChanged` is raised with the new view when the reader opens a month or a day, goes back or steps, and when a new `Spec` returns the planner to its whole period; a `View` the host sets is said in the status line (`Showing …`), and one outside the period throws `ArgumentException`. `EventSelected` is raised with the `PlannerEvent` when the reader clicks one or chooses it in a day with Enter or Space, and `DaySelected` with the date when a day is opened from a month. `ShowFilters` (default `true`) shows the chips: the regions as a tree, then category, audience, status and relevance, each group when it offers two or more values, a pressed chip bold with a thicker border and a check mark as well as `aria-pressed`, and `Clear filters`; hide them and filter through `Spec.Filter` where room is short, as on a 375 px phone where the toolbar and chips stand above the drawing. It draws at its box's width, 320 to 4096 px, in the narrow layout under 640 px, so there is no `FitWidth`; before it is interactive it is drawn at `Spec.Width`, wide. A click, or Enter or Space, on a day opens its month and on a day of a month opens the day; Escape and Back go out (Escape does nothing in the year); Previous and Next step months or days and stop at the period's edges; a day or month outside the period stays shut and the status line says `… is outside the planner`; a double-click acts as one click and a held key as one press. A new `Spec` keeps the view while it lies in the new period, else shows the whole period (`Showing …`), and keeps the reader's filter less the values it no longer offers unless its own `Spec.Filter` names them; a changed host `Spec.Filter` replaces the reader's (null counts as empty), and a pruned or replaced filter says `Filters updated`. Keys: one tab stop, with the keys named on the focused cell; arrows move between days (up and down by month in the year, by week in a month), weekends on a phone's year, agenda days and a day's events; Home and End go to the ends of the month, bar or list; Enter or Space opens or selects; Escape goes back; the focused cell is ringed in the text colour; after a button disables itself in a redraw the focus moves to the drawing's tab stop, and on a phone going back to the year puts it in the bar of the month just left; no redraw (a new width or spec included) drops the focus of a reader in the planner, the page scrolling to it only for their own key or click, and once they click or move elsewhere a redraw leaves focus and scroll alone; a phone's month with nothing scheduled makes the drawing itself the stop, Escape on it going back. Events in the year and in a month are clicked, or reached by opening their day; one a click has focused also takes Enter or Space.
- `<LumenPlacings Results="…" Options="…" Adjust="…" Static="false"><Empty>…</Empty></LumenPlacings>` (0.45.0) — draws `PlacingsChart.Build(Results, Options)`. `Results` (`IEnumerable<Placing>`, required) and `Options` (`PlacingsOptions?`) go to the builder; a cascaded `ChartStyle` (`<LumenBrand>` or a `CascadingValue`) is used when `Options.Style` is null. `Adjust` (`Func<ChartSpec, ChartSpec>?`) is the host's last word on the spec, such as `s => s with { Title = "Position & points by race", YLabel = "Position" }`; one that returns null shows `Empty`. `Static` writes `ChartSvg.Render(spec)` as plain markup with no script, at the spec's own width (340 unless `Adjust` changes it); otherwise it is a `<LumenChart FitWidth="true" ShowToolbar="false">`, needing an interactive render mode for its tooltips. `Empty` (`RenderFragment?`) is shown when no result has a place; without it nothing is drawn. The chart is rebuilt every time the parameters are set, and a `<LumenChart>` resets a drag-zoom when its spec is set, so a host render resets the reader's zoom. With change colours the lines are drawn in the style's rising and falling colours, while the legend shows each series' own colour.
- `<LumenBrand Series="--bs-primary, --bs-success" Background="--bs-body-bg" Text="--bs-body-color" Muted="--bs-secondary-color" Grid="--bs-border-color">…</LumenBrand>` reads the host page's CSS custom properties and cascades a `ChartStyle` to every chart inside. Or cascade one yourself: `<CascadingValue Value="Brand">…</CascadingValue>`.
