# Lumen.Charts

Lumen.Charts is a standalone C# chart library: no JavaScript charting engine and no CDN. The core renders a `ChartSpec` to an SVG string anywhere .NET runs; a Blazor component adds tooltips, zoom, legend toggles, a data table and exports; an ASP.NET Core package exposes it as an HTTP API. Source, docs and releases: https://github.com/jtheyse/lumen-charts (MIT). Libraries target .NET 8 and later.

Three packages — add only what the project needs:

| Package | Use it for |
|---|---|
| `Lumen.Charts` | Rendering to SVG or CSV from any .NET code: console apps, reports, background jobs, APIs. Also the training metrics. |
| `Lumen.Charts.Blazor` | The `<LumenChart>`, `<LumenGraph>`, `<LumenPlanner>` and `<LumenPlacings>` components in a Blazor Web App or WebAssembly app. Brings `Lumen.Charts`. |
| `Lumen.Charts.AspNetCore` | `app.MapLumenCharts()`: POST a chart as JSON, get SVG or CSV back. Brings `Lumen.Charts`. |

## 1. Install

The packages are attached to each GitHub release; they are **not on nuget.org**, so `dotnet add package` alone fails until a local feed exists. Run the bundled script from the **repository or solution root**, not from inside a web project's folder: the Web SDK copies a `nuget.config` it finds there into the build output and publishes it. The script it finds the latest release, downloads the three `.nupkg` files into `./local-packages`, and writes a `nuget.config` that lists that folder beside nuget.org (still needed for Lumen's own dependencies):

```bash
bash <skill-dir>/scripts/install.sh            # Git Bash, macOS, Linux
pwsh <skill-dir>/scripts/install.ps1           # Windows PowerShell 7
```

Both take an optional version tag (`v0.29.0`) to pin one. If the project already has a `nuget.config`, the scripts leave it alone and print the source line to add instead. Then:

```bash
dotnet add package Lumen.Charts.Blazor        # or Lumen.Charts / Lumen.Charts.AspNetCore
```

Commit `nuget.config` and `local-packages/` (three small files), or CI will not restore. To upgrade later, rerun the script and bump the version.

A machine that has restored Lumen before can do so from its NuGet cache without any of this, which hides a missing feed until CI or a colleague's machine fails. To prove the feed works, restore into an empty folder: `dotnet restore --packages <empty folder> --no-http-cache --force` — the log should say `Installed Lumen.Charts … from …local-packages`. Teams that want to stop a same-named package arriving from another feed can add `packageSourceMapping` to `nuget.config` (`Lumen.*` → the local source, `*` → nuget.org); note that once any mapping exists every package must map to a source, so include any private feeds the project already uses.

## 2. Draw something

**Anywhere (server, console, report):**

```csharp
using Lumen.Charts;

var spec = new ChartSpec {
    Title = "Monthly revenue", Description = "Revenue by month, ZAR thousands", Source = "Source: accounting export",
    Kind = ChartKind.Column, XLabel = "Month", YLabel = "Revenue (ZAR thousands)",
    Series = [new("Revenue", [new(1, 24, "Jan"), new(2, 38, "Feb"), new(3, 31, "Mar")])]
};
string svg = ChartSvg.Render(spec);          // self-contained SVG, write it to a file or a response
string csv = ChartExport.Csv(spec);          // the original observations
```

**Blazor:** add `@using Lumen.Charts` and `@using Lumen.Charts.Blazor` to `_Imports.razor`, put `<link rel="stylesheet" href="_content/Lumen.Charts.Blazor/lumen.css" />` in the host page's `<head>`, then `<LumenChart Spec="spec" PointSelected="OnPoint" />`. Rendering works in static server rendering, but the toolbar (zoom, pan, exports, data table), tooltips and callbacks need an interactive render mode (`@rendermode InteractiveServer`, or WebAssembly). `PointSelected` gives a `PointSelection(SeriesIndex, PointIndex)` into the original series. A season planner is `<LumenPlanner Spec="season" EventSelected="OnEvent" DaySelected="OnDay" />` (0.44.0), which zooms the year, a month and a day and filters them, and fits its own box. A rider's places and points is `<LumenPlacings Results="results" Options="words" />` (0.45.0), which builds the chart from a list of `Placing` records with `PlacingsChart.Build`.

Don't name a page or component `Training` (`Training.razor`): its generated class hides `Lumen.Charts.Training`, and `Training.Load(...)` then fails with CS0117. Call it `TrainingPage.razor` (keep `@page "/training"`), or write `Lumen.Charts.Training.Load(...)`.

Charts are drawn at `ChartSpec.Width` (900 by default) and scale down to their container, but the stylesheet keeps them at least 640 px wide and scrolls them sideways inside their own box below that, so text stays legible; while it scrolls the box is a keyboard stop (`role=region`), and from 0.42.0 a chart that fits its box has no such stop. For a phone layout or a narrow card, write `<LumenChart Spec="spec" FitWidth="true" />` (0.25.0 and later): once the component is interactive it measures its container, redraws at that width whenever it settles at a new one (never below 320 px), and lifts the 640 px minimum for that chart alone, so the chart fills its box with its text at its own size; zoom, hidden series and the exports keep working, at the fitted width. Before that, in the prerender or in static rendering, it is drawn at `Width` and scaled to fit. `Height` is kept, so choose one that reads well on a phone too: a chart is at least 240 units tall (a sparkline at least 60 by 16), except a strip and a bar chart with `FitHeight = true` (0.41.0), drawn as tall as their content. Only for SVG rendered on the server with `ChartSvg.Render`, which nothing measures, set `Width` to the width it will be shown at (about 340 to 360 on a phone) yourself; from 0.35.0 a description or source too wide for that width goes on over a second line and a long title is cut with `…`, instead of running off the drawing.

The root `<svg>` carries its own layout and font in its `style` attribute (`width:100%;height:auto;display:block`, or a sparkline's own width, with its background, colour and font family). Don't add a `style` attribute to it, or replace that one, from the host page: a second `style` attribute makes the SVG invalid XML (an HTML page silently ignores it), and a replaced one drops the chart's sizing, background, text colour and font. To size, place or frame a chart, wrap it in an element and style the wrapper: `<div class="card-chart">@((MarkupString)svg)</div>`. A host rule such as `svg{max-width:100% !important}` overrides the width a fixed-width chart holds itself to (a `CellWidth` heatmap, and the copy of its row names that `<LumenChart>` freezes) and stretches or squeezes it; leave Lumen's drawings out of such a rule, for example `svg:not(.lumen-chart svg)`. A static SVG has no `.lumen-chart` around it, so wrap it in an element of your own and exclude that. `<LumenGraph Spec="graph" FitWidth="true" />` (0.30.0 and later) does the same for a network graph: it is drawn as `GraphEngine.Fit(graph, width)` lays it out, so a layered graph whose levels cannot stand side by side turns top to bottom (`GraphSpec.Direction = GraphDirection.TopToBottom`) and grows taller, and a circular one grows taller; for server-rendered SVG call `GraphEngine.Fit` yourself.

**HTTP API:** see `references/http-api.md`.

## 3. How a chart is described

Everything is one immutable `ChartSpec` record; change one with `with { … }`. The full member list is in `references/api.md` — read it before using anything not shown here. From 0.25.0 the packages also carry XML documentation beside each DLL, so IntelliSense shows what a member does, and you can read it in the NuGet cache (`~/.nuget/packages/lumen.charts/<version>/lib/net8.0/Lumen.Charts.xml`, and likewise for `lumen.charts.blazor` and `lumen.charts.aspnetcore`).

- `Kind` picks the chart: `Line, Area, Scatter, Bubble, Column, Bar, StackedColumn, Donut, Heatmap, Radar, Candlestick, Ohlc, Band, Histogram, Box, Violin, Gauge, Ring, Timeline, Range, Calendar, Blocks, Strip`.
- `Series` is a list of `ChartSeries(name, points, color?)`; a point is `ChartPoint(x, y, label?, size)`. A null `y` is a missing observation, drawn as a gap, never as zero. `ChartSeries.From(name, items, x, y, label)` maps your own objects.
- Category charts (column, bar, stacked, donut, radar, heatmap) place points by order and show their `Label`; continuous charts (line, area, scatter, bubble, band, range, blocks, candlestick, OHLC, timeline) place them by `X`.
- **Gauges and rings** (0.26.0 and later) draw one point per series round an arc, with no X axis. `ChartKind.Gauge`: one series of one point, `Y` the score and its `Label` the caption; the scale is `YMin`–`YMax` (0–100 unless set), `GaugeSweep` 180–360 degrees (270 by default), `YLabel` the unit (`"%"`), `YZones` tint the track and colour the score, a Y annotation is a target tick. `ChartKind.Ring`: one to six series, outermost first, one nonnegative point each, `ChartSeries.Goal` the target (100 unless set) and the point's `Label` the unit; past its goal a ring runs on over itself. Recipes in `references/sports.md`.
- **Timelines and range bars** (0.27.0 and later). `ChartKind.Timeline` is a state timeline such as a sleep hypnogram: one series per state, drawn as a lane top to bottom in series order, each point a span made with `ChartPoint.Span(start, end, label?)` (it sets `XEnd`; there is no `Y`). Spans in one lane must not overlap; where one ends exactly as one in another lane starts, a connector joins them unless `TimelineConnectors = false`. The legend reads `REM 1:42, 22 %`. `ChartKind.Range` draws floating bars from `Low` to `High` with a dot at `Y` when set, made with `ChartPoint.Interval(x, y, low, high, label?)` (pass `null` for no dot); no zero baseline, so reversed and log axes are fine. It is also a series `Kind` beside lines or in a column chart's slots.
- **Calendars** (0.28.0 and later). `ChartKind.Calendar` draws one series of days on a time axis (`XAxis = AxisKind.Time` is required): each point's `X` is a moment counted on its day in `TimeZone`, its `Y` the day's value, and one day's points add up; zero or null is a rest day, an empty grey cell that takes no focus. `CalendarLayout.Weeks` (default) is the contribution grid, a column per week, weeks starting on `WeekStart` (Monday unless set); `CalendarLayout.Months` is a small grid per month. `CalendarCell` is `Square` (default), `Dot` or `Bubble` (area by value). `YZones` colour each day by its tier; without them days take a ramp that steps up from the empty cell's grey to the style's `HeatmapHigh` (0.30.0), which reads on light and dark styles alike. An X annotation outlines a day (today, a race). `XMin`/`XMax` set the first and last day shown.
- **Blocks** (0.29.0 and later) — laps sized by their length and structured workouts. `ChartKind.Blocks`, or a series' `Kind = ChartKind.Blocks` beside lines on a continuous chart: each point is `ChartPoint.Block(start, end, height, label?)` (it sets `X`, `XEnd` and `Y`), drawn exactly from `X` to `XEnd`, standing on the bottom edge of its plot and rising to `Y`. With `IncludeZero = true` a power target rises from zero; on a reversed pace axis (`YReversed = true`, `YFormat = ValueFormat.Duration`) a lap rises from past the slowest pace, since an axis fitted to the data reaches below its lowest block until that block stands a sixth of the plot. Blocks that touch are a hairline apart; `Zones` colour each by its height's zone (`ZoneScale.CogganPower(ftp)`), a point's `Color` beats it, and a line series drawn with them stands over them. Blocks in one series must not overlap (they may touch). Recipes in `references/sports.md`.
- **Time on X:** `XAxis = AxisKind.Time` and X in **Unix milliseconds** — `TimeAxis.Value(DateTimeOffset)` converts. `TimeZone = "Africa/Johannesburg"` reads the calendar locally; `SkipWeekends`/`TimeSkips` close trading gaps.
- **What labels the X axis** (0.33.0): points' `Label`s replace a continuous axis's ticks when 1–24 labelled points are in view, cut to 12 characters — except on a time axis, which keeps its dates unless every label fits uncut, the longer names staying in the tooltips. `XTicks = TickSource.Axis` always draws the axis's own ticks, `TickSource.PointLabels` always the labels. To place points evenly by index with text under each (races, rounds, weeks), use X = 0, 1, 2… with a `Label` each and `XMin = -0.5, XMax = count - 0.5`, so the first and last labels stand clear of the edges.
- **Durations and pace:** `XFormat`/`YFormat = ValueFormat.Duration` reads values as **seconds** (`5:30`, `1:02:05`; on a log axis `1s`, `5m`, `1h`). Pace is seconds per unit, so 300 reads `5:00`; `YReversed = true` puts the faster pace on top. `ValueFormat.Compact` writes `1.2k`. `ValueFormat.TimeOfDay` reads **seconds since a midnight** as `HH:mm` and wraps at 24 h, so a night runs as one span: 23:30 is 84600 and 06:40 the next morning 110400; with `YReversed = true` it draws sleep timing, earlier at the top. Linear axes only.
- **Log axes:** `XAxis`/`YAxis = AxisKind.Log`, positive values only.
- **Second axis:** `Secondary = true` on a series measures it on the right; name it with `Y2Label`.
- **Several marks in one chart:** a series' `Kind` overrides its mark — lines over columns, a band behind a line, range bars beside a line. The chart's own `Kind` still decides the X layout.
- **Panes:** `ChartSeries.Pane = 1` puts a series in a pane beneath the main plot, configured by `ChartSpec.Panes[0]` (pane *k* is `Panes[k − 1]`). All panes share one X axis and zoom together.
- **References:** `Annotations = [new(AnnotationAxis.Y, 55) { Label = "Target" }]`, or a band with `To`. The value is printed after the label (`Target: 55`), so keep the label plain and round the value you pass. From 0.35.0 `ShowValue = false` draws the label alone (`median`) while its tooltip and accessible name still read `median: 47:12`, and `InFront = true` draws the line or band over the data instead of behind it, on a halo of the background colour, so bars and blocks do not hide it (a median over bins, a target over columns).
- **Zones:** `ChartSeries.Zones` colours a line by the zone each value is in; `ChartSpec.YZones` shades the zones behind the data.
- **Look:** the default *refined* finish draws thin non-scaling lines, shows point markers on hover or focus, and uses a dotted hairline grid. `Style = ChartStyle.Midnight` is a dark athletic preset; `ChartStyle.Light with { Finish = ChartFinish.Classic }` restores the pre-0.24 look. Per series: `StrokeWidth`, `Curve` (`Smooth`, `Step`), `Fill = AreaFill.Fade`, `Gradient`, `Markers`, `HighlightLast`, `ValueLabels`. Brand colours: `references/api.md` → ChartStyle.
- **Change colours, value labels and notes** (0.33.0): `ChangeColors = ChangeColors.LowerIsBetter` (a finishing position, a pace, a ranking) or `HigherIsBetter` (points, a price) colours each point of a line or scatter series, and the segment arriving at it, in the style's `Rising` colour when it beat the nearest earlier value and `Falling` when it did worse, and names the change in its tooltip (`, better than the previous`) — so colour is never the only cue; it is by the setting, not the screen, so it holds on a reversed axis. `ValueLabels = true` now writes values above a line's or scatter series' points too, in the point's colour where it clears 4.5:1 against the background (else the text colour), moved in from the plot's edges and below the point where there is no room above. `ChartPoint.ValueNote` (≤ 20 characters, e.g. `"/48"` for a field size) follows the value in the label (muted), the tooltip, the component's table and a CSV `Note` column.
- **Sparklines, highlights and a minimum span** (0.34.0): `Sparkline = true` draws a line, area, scatter or column chart's data alone at the size of a word (60 by 16 at the smallest, e.g. `Width = 120, Height = 32`): no axes, gridlines, legend or text, the plot filling the drawing but for room for its largest ring, shown at its own width; its `Title` and `Description` stay its accessible name, every point a named, focusable mark. Write the numbers in the page beside it. `ChartPoint.Highlight = "#E30613"` rings one point of a line or scatter series in that colour, whatever the markers; give it a `ValueNote` such as `" · PB"` so its tooltip says why — never colour alone. `YMinSpan = 8` keeps a Y axis at least 8 tall, centred on the data, so a small wobble (a weight) reads as steady; refused beside `YMin`/`YMax`, on log axes and on axes held at zero.
- **A histogram of your own bins, end labels and text that fits** (0.35.0): draw bins you have counted (finish times, response times) as `ChartKind.Blocks`, each `ChartPoint.Block(from, to, count)`, with `IncludeZero = true`; a block above the bottom of its axis is now drawn at least 2 px tall, so a bin of one among hundreds still shows, and a bin of none stays named and focusable. (`ChartKind.Histogram` bins raw observations itself.) `XTickLabels` chooses the X axis's labels as `YTickLabels` does the Y axis's: `TickLabels.All`, `Ends` (the first and last drawn) or the new `Bounds`, which labels only the axis's two ends at their exact values in its format (`35:00` … `1:20:00`), for X or Y; gridlines stay. A `Description` or `Source` wider than the drawing less 48 wraps to two lines (the source growing upward) and the plot gives up 14 px for it; past two lines it ends in `…`; a `Title` stays one line, cut with `…`; the whole text stays in `<title>`, `<desc>` and the accessible name. Recipe: "How the field finished" in `references/recipes-race-face.md`.
- **Reading a chart day by day** (0.36.0): every `<LumenChart>` has one roving point stop, its only tab stop while its drawing fits (from 0.42.0; a drawing that scrolls adds its viewport's own, a `role=region`), and the arrow keys move between its points (Left/Right along a series, skipping gaps; Up/Down to the next series; Home/End; Page Up/Down ten). `SharedReadout = true` reads every series at once at one X in the component — a guide through every pane, a ring round each point, one tooltip in legend order, the keys stepping by X and the status line reading it — and never changes the SVG; `ChartSvg.Readout(spec)` gives the same table to other hosts. `YSymmetric = 10` (spec or `ChartPane`) holds a Y axis symmetric about zero, at least ±10, and `ValueFormat.Signed` writes `+5` and `−5`: form (TSB) in a pane of its own. Recipe: "Fitness & form" in `references/recipes-race-face.md`. Test the keys with real input, such as Playwright's `keyboard.press`: a `KeyboardEvent` dispatched from script can move focus without bringing up the readout.
- **Ride channels** (0.37.0): a 1 Hz stream of several channels, each in a plot of its own. `Sampling = SamplingMethod.Average` draws a long line or area as the means of `MaxRenderedPoints` equal slices of the X range shown, the same slices for every series, each average rounded to the series' own precision and named `, average of 12 points` (the readout says it once a column); a run longer than the budget is thinned over `XMin`–`XMax` only, so zooming shows more detail; the shared readout reads the drawn points. Up to six plots (`Panes` takes five). `ChartPane.YTickLabels` labels a pane's own ticks, and `TickLabels.None` writes none. `PaneTitles = PaneTitlePlacement.Above` names each plot on one line above it (`YLabel`, each pane's `Label`), and with no label up the left the margin narrows to 30. In the component a mouse or pen drag across the plots zooms to it; `ChartSvg.Plot(spec)` gives where the plots and X axis stand. If the app already buckets its channels, pass those points and leave `Sampling` alone. Recipe: "Ride channels" in `references/recipes-race-face.md`.
- **Season arcs and gaps to the leader** (0.38.0): `YTickValues = [new(0, "Front"), new(50, "Mid"), new(100, "Back")]` (`AxisTick`, also on `ChartPane`) sets an axis's ticks by hand, each labelled as given or in the axis's format; values outside the axis are left out. `YUnit = "s"` writes a unit after every value the left axis writes (`+12.3s`), ticks, names, value labels, readout and the component's status and table, never after a hand-written tick label. `ChartSeries.EndLabel` and `EndNote` name a line, area or scatter series at its end in its colour (text colour under 4.5:1), the note muted, moved apart where lines end close together, in a right margin that grows up to half the drawing (≈ 10 characters at 340, so use short names) and cut with `…` past it; the last point's name says them. Then drop the legend: `includeLegend: false`, or `<LumenChart ShowLegend="false" />`. `ShowToolbar="false"` leaves out the component's buttons for a phone card while keeping its status line for screen readers (it also takes away the keyboard's zoom and the data table). A large spec on an `InteractiveServer` island can pass SignalR's 32 KB message limit and close the circuit silently: raise `MaximumReceiveMessageSize` with `AddHubOptions`, or let the island load its data.
- **Proportions and meters** (0.39.0): `Kind = ChartKind.Strip` draws one series' points as the parts of a whole on one bar — each point's `Label` its name, `Y` (≥ 0) its amount, `Color` its colour — parted by gaps, with a key under it of every part's whole percentage, adding up to exactly 100; parts are named `Easy: 24%, 12:20` (`YFormat`, `YUnit`), and it is drawn as tall as its content, so `Height` is not used. Time in zone: `Training.TimeInZone(samples, zones)` gives the amounts. `BarTrack = true` on a `Bar` or `Column` chart with `YMin = 0`, `YMax = 100` draws a track behind each bar to `YMax`, value labels past the track's end; pair it with `YTickLabels = TickLabels.None` and `YTickValues = []` for a clean meter. `DrawTitles = false` keeps `Title` and `Description` as the accessible name without drawing them, for a page with its own heading (`Render`'s `includeTitles` only controls each mark's native tooltip). Recipes: "Effort zones" and "Score bars" in `references/recipes-race-face.md`. Pass a strip raw amounts (seconds), not rounded shares; from 0.40.0 a part whose amount writes as its share is named once, `Moderate: 30%`.
- **Lap columns and best efforts** (0.40.0): `Gradient = [new(0, "#A88200"), new(174, "#DD4B45")]` on a column series, or a bar chart's series, fills each column by value along the value axis, so each shades towards the last colour as it rises and harder laps reach further into it (put the first stop at the base, 0, or the columns' lower parts stay one flat colour) (not on stacked columns or with a faded fill); a point's `Color` still wins. `ChartPoint.SubLabel = "152 bpm"` (≤ 16 characters) writes a second line under a category's name on column, stacked column and bar charts (from 0.46.0 also inside a heatmap's cells, each its own), said in each mark's name (`Heart rate: L3 · 168 bpm, 168`); columns with sub-labels thin by the width of their words, so at 340 keep them short (`152 bpm` fits four columns, a bare number about eight). Column axes start at zero. End labels now give up their note before their name. Recipes: "Best efforts" and "Heart rate per lap" in `references/recipes-race-face.md`; the curve view is "Power–duration curve with critical power" in `references/sports.md`.
- **Fits a card** (0.41.0): `FitHeight = true` on a `Bar` chart (and, from 0.46.1, a `Heatmap`, 36 units a row) draws it as tall as its rows need (36 a row on tracks, 32 without, 38 with sub-labels, plus the title, axis and source it draws), so three meters with `DrawTitles = false` and `YTickLabels = TickLabels.None` are 160 units tall rather than 240; other kinds refuse it. `PaintBackground = false` (on `ChartSpec` and `GraphSpec`) leaves the background unpainted so a card of another colour shows through; set `Style.Background` to that card's colour, since contrast checks, halos and separators still use it. `ChartSeries.AverageOf = "12 s"` says the app averaged a series' points: each mark's name and tooltip end `, average of 12 s`, and the shared readout and status line say it once a column (`1:02:30 · average of 12 s`) where every series there shares it; Lumen's own `SamplingMethod.Average` words win where it averaged.
- **Words at a missing value** (0.42.0): `new ChartPoint(i, null, "Round 6") { GapLabel = "absent" }` on a line, area or scatter series writes `absent` at that X, at the foot of the plot (the top on a reversed axis), in the point's `Color`, the series colour or the text colour, whichever first clears 4.5:1, and makes the missing point a focusable mark named `Share: Round 6, absent` that the arrow keys and the shared readout reach; the line still breaks. A round that was not held gets no point, so the line joins over it. ≤ 12 characters; refused on a valued point, other kinds (a heatmap cell with no value takes one from 0.46.1, as a "did not race" cell, unless it is also `NotRated`) and sparklines. In `<LumenChart>` a chart that fits its box is one tab stop; its viewport becomes a `role=region` stop only while it scrolls. Recipe: "Team rider" in `references/recipes-race-face.md`.
- **Season planners** (0.43.0): `PlannerSpec` + `PlannerSvg.Render(spec, view, layout)` — a year aligned by weekday, a month, a day; holidays, weekends, events by relevance and region; `PlannerSvg.Table` for the month in words. A `PlannerSpec` is a period of at most 400 days (`PlannerSpec.ForYear(2027)`) with `Regions` (`PlannerRegion(code, name, parent?)`, a hierarchy), `Periods` (`PlannerPeriod(from, to, name, PeriodKind, region?)`: public holidays, school holidays, other periods such as exams, drawn as a dotted band) and `Events` (`PlannerEvent(id, name, start)` with `End`, `Region`, `Category`, `Audience`, `Status`, `Relevance`, `Mine`, `Note`, `Url`); `Filter = new PlannerFilter { Regions = ["ZA-GP"] }` shows a province's events and the country's holidays. `PlannerView.WholePeriod`, `Month(year, month)` or `Day(date)`; `PlannerLayout.Narrow` for a box under 640 px. **The app decides `Relevance`** (`Clash`, `Near`, `Other`); the planner only draws it, by weight and dash (clash bold, close dashed, other thin and muted), provisional as outline and hatching, cancelled as outline and a strike line, yours outlined, each also said in words in every name and tooltip; a cancelled event counts as neither clash nor close in any count, and a week's number in the year is its clashes and close events counted together. The text is 10–12 units, so render `Width` equal to the box's CSS width. View only, at most 400 days, three stripes a day in the year, a multi-day event listed on each day in the month view. **Interactive** (0.44.0): `<LumenPlanner Spec="season" @bind-View="view" EventSelected="OnEvent" DaySelected="OnDay" />` zooms from the year to a month to a day by click or arrow keys and Enter (Escape or Back goes out; Previous and Next step and stop at the period's edges), shows filter chips for region, category, audience, status and relevance (`Spec.Filter` is where the reader starts; `ShowFilters="false"` hides them), draws at its box's width and in the narrow layout under 640 px by itself (no `FitWidth`), and needs an interactive render mode. `POST /api/charts/planner/svg` in `references/http-api.md`. Recipe: "Season planner" in `references/recipes-race-face.md`.
- **Places and points** (0.45.0): `PlacingsChart.Build(results, options)` turns a list of `Placing(place)` records, each with optional `Field`, `Points`, `Date`, `Label` and `Series`, into an ordinary `ChartSpec`, or returns `null` when no result has a place: finishing places on a reversed axis (first at the top), one line per series with each place named and coloured by its change against the previous race of the same series (`Place: 16-05-2026, 24/48, better than the previous`), the field after each place, and the points in a pane beneath. A place of 0 or less is dropped; races are drawn in date order when every one has a date, else as given; a race's label is its `Label` (blank counts as missing), else its `Date` in `DateFormat`, else `Unlabelled` with its number. A line holds points only at its own races and draws joined across the other series' races; a race without points is never a zero: a gap in the points line of a series that scores elsewhere, no mark (the line joins across it) in one that never scores; with no points there is no pane (260 tall instead of 380, 340 wide). `PlacingsOptions` sets `PlaceName` ("Place"), `PointsName` ("Points"), `DateFormat` ("d MMM yyyy"), `Unlabelled` ("#{0}"), `PlaceColors`, `PointsColor` and `Style`; by default the places lines take the style's series colours in order, less any near its rising or falling colour, and the points the next one; the X axis keeps every race's label, thinned beyond 24. The title ("Places and points"), description, `YLabel` and size are set on the returned spec with `with { … }`. A blank name or date format, an `Unlabelled` without `{0}`, an empty `PlaceColors`, a null result, a style with an empty palette the defaults need or more than 32 lines (series plus points) are refused with an `ArgumentException` naming the option. In Blazor: `<LumenPlacings Results="results" Options="words" Adjust="Adjust" Static="false"><Empty>…</Empty></LumenPlacings>`, a fitted `<LumenChart>` without a toolbar (or plain SVG with `Static`, at the spec's own width) that shows `Empty` when nothing is placed, rebuilds on every parameter set (so it resets a reader's zoom) and takes a cascaded style when `Options.Style` is null. Recipe: "Position and points by race, recommended: two panes" in `references/recipes-race-face.md`; the hand-built spec stays there as the explanation.
- **Heatmap tables** (0.46.0, followed up in 0.46.1): a `ChartKind.Heatmap` is a row for each series and a column for each X, each point a cell shaded on the style's `HeatmapLow`→`HeatmapHigh` ramp; four options, all off by default, make it a table of results. `CellText = true` writes each cell's value (in `YFormat` and `YUnit`, now accepted on heatmaps) and, under it, the point's `SubLabel` (≤ 16 characters, each cell's own: `/12 starts` and `/4 starts` may share a column), 11 and 10 px, in the style's text or background colour where that clears 4.5:1 on the cell and otherwise in black or white, so every cell writes its value; a sub-label that does not fit is dropped first, then the value, and the cell's name always says both. `ChartPoint.NotRated = "too few starts to rate"` (1–24 characters) marks a cell that is not a result: unshaded, dashed in `Muted`, left out of the colour scale, and drawn even when `Y` is null (a null `Y` without it draws no cell); with `CellText` it writes its reason in the cell in place of its value, as 10 px lines 12 apart, wrapped at word breaks onto as many as fit the cell's height less 4, each within its width less 6, then the sub-label if a line is left, cut with `…` where it does not fit (0.46.1; "too few starts to rate" is whole on two lines at `CellWidth = 90`). `CellWidth = 90` (≥ 24) gives every column that width, so the drawing is the name column + 35 + columns × 90 wide (the name column is 130 while every name fits 118 units at 12 px, so 165 + columns × 90; never under 320, `Width` unused, over 4096 refused) and in `<LumenChart>` is shown at exactly that size, scrolling sideways in a narrower box instead of squeezing, with or without `FitWidth`; column labels are thinned to keep clear of each other. Cells are named as a column chart's marks are, `Sprint: 2025 · /12 starts, 2.8 · 34 pts, 5 riders` (row, column, ` · ` sub-label, value, then `ValueNote`, which brings its own separator, may be up to 40 characters on a heatmap cell (20 elsewhere) and is never drawn in the cell), and a not-rated one ends `, not rated: too few starts to rate`. `ChartExport.HtmlTable(spec)` returns the same cells as a `<table class='lumen-grid-table'>`, rows by columns with `scope` headers, each cell reading its value, ` · ` and the sub-label, the note as written, then `, not rated: …` (0.46.1's order; 0.46.0 put the note first), for a static page and screen readers (heatmaps only; on a static page wrap it in `<div class="lumen-table" tabindex="0" role="region" aria-label="Chart data">`, which `<LumenChart>`'s "View data" uses for a heatmap too, and which has no side margins of its own from 0.46.1); CSV gains a `NotRated` column when a cell is not rated. In the refined finish the scale line reads `Color scale: 1.7 low to 3.5 high` (the classic keeps `(light) to (dark)`), and a style that keeps the default ramp on a dark background draws `#22304A`→`#6E9BFF`. Recipe: "Category heatmap" in `references/recipes-race-face.md`.
- **Heatmap follow-ups** (0.46.1): `GapLabel = "did not race"` on a heatmap point with a null `Y` (1–12 characters; refused beside `NotRated` and on a valued point) draws an unshaded, dashed cell, out of the colour scale, that writes its word and is named `Junior mixed team relay: 2023 · /0 starts, did not race`, its column kept like any other. In the refined finish `YMin`, `YMax` and `IncludeZero` pin the colour scale's ends as given (`Color scale: 0 pts low to 3.5 pts high`; a value past an end takes its colour; the classic finish ignores all three). `ColumnLabelsOnTop = true` writes the column labels above the grid (heatmaps only). The refined name column is measured: 130 units while every name fits 118 and otherwise the widest name + 18, up to 240, names cut by width with `…` (the classic keeps 130 and cuts at 17 characters; even a name of 17 characters or fewer can widen it). `FitHeight = true` draws a heatmap 36 units a row (80 above the rows and 80 below, less 26 with the labels on top and 24 with an empty `Source`; the 240 floor applies). In `<LumenChart>` a `CellWidth` heatmap's row names stay at the left while the cells scroll, in a second, cropped copy of the drawing that covers the grid's rows and the row of column labels, is `aria-hidden` and not `inert` (it takes the pointer, so a cell under it can't be hovered) and is painted in `Style.Background` even with `PaintBackground = false`; `ShowToolbar="false" ShowDataButton="true"` keeps only "View data" (unset, `ShowDataButton` follows `ShowToolbar`). Limits: static SVG does not freeze row names, and there is no sticky header row; `FitHeight` rows are 36 units (a table below the 240 floor is drawn at it); a reason longer than its cell is cut with `…`; with narrow columns (about 24 to 60) the frozen copy clips the first column label's overhang at rest; Lumen decides nothing about which cells are rated or which seasons nobody raced.
- Always set `Title`, `Description` and axis labels: they become the SVG's accessible name and the screen-reader text.

## 4. Sports and training charts

For a race-results app — a rider's finishing places and points race by race (one call, `PlacingsChart.Build`), a season on a time axis, personal-best and growth-log sparklines, how a race's field finished as a histogram of the app's own bins with the reader's bin and the median marked, a season's arc through its fields by discipline, a race's gaps to the leader lap by lap with each rider named at the end of their line, a ride's effort zones as a strip and scores on meters, a ride's best efforts and a race's heart rate per lap as columns with a second label line, a category-by-season heatmap table whose cell says its starts, whose thin cell is marked not rated with its reason and whose long names stay in view, a dark brand style from design tokens checked with `ContrastIssues()`, phone-width static SVG, an organizers' season planner of weekends, holidays and other organizers' events — read `references/recipes-race-face.md`.

For fitness, training, wearable or health data, read `references/sports.md`. It has tested recipes for the performance management chart (CTL/ATL/TSB from `Training.Load`), a recovery or readiness gauge, activity rings, a multi-pane activity stream with heart-rate zones and reversed pace, the power–duration curve with a critical-power fit, time in zone, weekly load against a target band, an HRV baseline band, grade-coloured elevation and a personal-best step line, a sleep hypnogram, sleep timing, daily heart-rate ranges, a training calendar, laps sized by their length and a structured workout in power levels — and the conventions the numbers follow (seconds, Unix milliseconds, zone bounds).

## 5. When a chart is refused

`ChartSvg.Render` validates first and throws `ArgumentException` with a plain message; the HTTP API answers 400 with the same message. Read the message — it names the rule. The ones projects hit most:

- Time values must be Unix milliseconds (not ticks, not seconds), between year 1 and 9999.
- Log axes refuse zero and negative values; a log Y axis refuses column, bar, area, histogram, donut and radar charts, which need a zero baseline.
- Line, area, candlestick, OHLC and band points must be ordered by X.
- Column and area series draw from zero, so their axis always includes zero and cannot be logarithmic or reversed.
- Candlestick and OHLC take exactly one price series (`ChartPoint.Candle`); other series beside it must set their own `Kind`.
- Panes need a continuous chart (line, area, scatter, bubble, band, candlestick, OHLC), at most five (six plots with the main one; four before 0.37.0), and every `Pane` index needs its `ChartPane`. `TickLabels.None` is refused on `XTickLabels`; `PaneTitles = Above` on a horizontal bar chart, a sparkline and the kinds without a Y axis up the side.
- A zone scale's last `Upper` must be `double.PositiveInfinity`; in JSON write `"Infinity"`.
- A gauge takes one series with one point and a scale with `YMin` below `YMax`; a ring chart one to six series of one nonnegative point each, each `Goal` positive. Both refuse time, log and reversed axes, panes, secondary series, trends and series kinds, and rings refuse zones and annotations.
- A timeline needs every point to be a span (`XEnd` above `X`), refuses overlapping spans in one lane, and refuses Y-axis settings, zones, trends, secondary series, series kinds, panes and Y annotations (X annotations are fine). A range point needs both `Low` and `High`, its `Y` between them; range series refuse `ProjectedFrom`, trends and zones. `XEnd` is for timelines only, and `ValueFormat.TimeOfDay` is refused on time and log axes.
- A calendar needs a time X axis and takes one series of nonnegative values; it refuses Y-axis settings (log, reversed, bounds, side, tick labels), secondary series, panes, trends, series kinds, series zones (use `YZones`), Y annotations and X annotation bands, `XEnd`, point colours, `SkipWeekends`/`TimeSkips` and spans over 3,660 days. `CalendarLayout`, `CalendarCell` and `WeekStart` are refused on other kinds.
- Blocks need every point to be a block (`XEnd` above `X`, and a `Y`), refuse overlapping blocks in one series, a column chart (no category slot for a block), a logarithmic X axis, `Trend` and `ProjectedFrom`, and the line-only finishes (stroke width, curves, markers, fades, value labels, gradients). `XEnd` is for timelines and blocks only.
- A sparkline takes line, area, scatter and column charts (series drawn as those marks), 60–4096 by 16–2160, and refuses panes and `ValueLabels`; a chart that is not one keeps 320 by 240 as its smallest. `Highlight` applies to points of lines and scatter series (not areas, not a density scatter). `YMinSpan` is refused beside `YMin`/`YMax`, on a log axis, with `IncludeZero`, on kinds drawn from zero and on an axis carrying columns or an area.
- `ChangeColors` applies to series drawn as lines or scatter points in X order, and not beside `Zones`, a `Gradient` or point `Color`s; `ValueLabels` to columns, bars, lines and scatter points; a `ValueNote` is at most 20 characters (40 on a heatmap cell, from 0.46.1) and is refused on candles, range bars, histograms, boxes, violins, timelines, calendars, gauges and rings; `XTicks` applies to the continuous kinds (line, area, scatter, bubble, candlestick, OHLC, band, range, blocks).
- `XTickLabels` applies to the continuous kinds and timelines, and `Bounds` is refused beside `XTicks = TickSource.PointLabels`; `ShowValue = false` needs a `Label` to draw and is refused on a calendar; `InFront` is refused on a gauge and a calendar.
- A planner refuses a blank title, a width outside 320–4096, a period that ends before it starts or runs past 400 days, an empty or repeated `Weekend`, a repeated, blank or unknown region code or a parent that loops, a blank or backwards period or event, a repeated event id, an event wholly outside the period, a note past 120 characters, a title, description or name past 200, more than 2000 events, 1000 periods or 500 regions, a list or item left null, an undefined enum value, a month that misses the period and a day outside it; the same messages come back as 400 from the endpoint.
- `CellText`, `CellWidth`, `ColumnLabelsOnTop` and `NotRated` are refused on every kind but a heatmap; a `CellWidth` below 24, not finite, or making the drawing wider than 4096 (the message gives the columns and pixels); a `NotRated` that is blank, over 24 characters or has a line break; and `Y2Format` on a heatmap (`A heatmap has no secondary axis, so it takes no Y2 format; its cells' values take YFormat.`). `YFormat`, `YUnit` and `SubLabel` are accepted on heatmaps from 0.46.0 (donut, radar and histogram charts still refuse a format), and a heatmap does not hold a category's sub-labels to one. `ChartExport.HtmlTable` refuses any other kind. From 0.46.1 a heatmap `ValueNote` past 40 characters is refused (`A value note is at most 20 characters (40 on a heatmap cell, where it is never drawn), …`), as is a `GapLabel` beside a `NotRated` (`A heatmap cell is either not rated or has a gap label, not both: …`) or on a cell with a value, and `FitHeight` on any kind but a bar chart or a heatmap (`FitHeight works out a chart's height from its rows, …`).
- A places chart refuses a null result, a blank `PlaceName`, `PointsName` or `DateFormat`, a `DateFormat` that cannot format, an `Unlabelled` without `{0}`, an empty `PlaceColors` and a style with an empty palette where the defaults need it, each with an `ArgumentException` naming the option; a list with no placed result is not a refusal, it returns `null`.
- Limits: 100,000 points per chart, 32 series.

## 6. Check the result

Don't hand back a chart nobody has looked at. Render it and look:

```csharp
File.WriteAllText("chart.svg", ChartSvg.Render(spec));   // open in a browser
```

For Blazor, run the app and open the page; hover a point to see its tooltip. If the project has tests, assert on the SVG (it is plain XML: `XDocument.Parse(svg)`) rather than on pixels. Contrast-check a custom brand with `style.ContrastIssues()`.

## Limits worth knowing

No server-side PNG (PNG export rasterizes in the browser), no PDF, no 3D, no map tiles (routes are out of scope), no streaming transport, no shared crosshair across panes. Vendor scores (WHOOP recovery, Garmin readiness and similar) are not computed — their formulas are unpublished — but a score the data provides draws on a `Gauge`, or as any other series.
