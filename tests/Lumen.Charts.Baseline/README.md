# Rendering-hash baseline

Every release proves which renderings it moved. This harness renders a fixed set of charts — every kind in light and dark, with and without native titles, plus named rows for each feature — and writes one SHA-256 prefix per rendering. A release that should change nothing must reproduce the previous release's hashes exactly; a release that adds a feature may only add rows.

```powershell
dotnet run -c Release                      # refined finish → baseline.txt
dotnet run -c Release -- classic           # classic finish (0.23.0's look) → classic.txt
dotnet run -c Release -- mine.txt          # any argument ending .txt names the output
dotnet run -c Release -- svg-out <dir>     # also writes each rendering, for a contact sheet
```

`reference/refined.txt` and `reference/classic.txt` are the hashes of **v0.46.0**, 392 rows, recorded by its verification: v0.45.0's 388 rows, all reproduced exactly in the classic finish and 384 in the refined, where four changed by design (`Heatmap/Light/True`, `Heatmap/Light/False`, `Heatmap/Dark/True` and `Heatmap/Dark/False`, which gain the colour scale's `low to high` words, and the two Dark rows the dark ramp), with 0.46.0's four heatmap-table rows added in each finish (`heatmap-table/light`, `heatmap-table/dark`, `heatmap-table/midnight`, `heatmap-table/cell-width`). v0.45.0 recorded 388 rows: v0.44.0's 385 rows reproduced exactly in both finishes, with 0.45.0's three places-and-points rows added (`placings/points`, `placings/no-points`, `placings/two-series`). v0.44.0 recorded 385 rows: v0.43.0's 385 rows, 381 reproduced exactly in both finishes and four changed by design (`planner/year-light`, `planner/year-dark`, `planner/year-midnight` and `planner/gauteng`, whose every day gains an unpainted `rect.lumen-cell` that a pointer can hit; nothing visible moves). v0.43.0 recorded 385 rows: v0.42.0's 373 rows reproduced exactly in both finishes, with 0.43.0's twelve planner rows added (the year, March and a day in light, dark and Midnight, the narrow year and March at 340, and a year filtered to one province). v0.42.0 recorded 373 rows: v0.41.0's 368 rows reproduced exactly in both finishes, with 0.42.0's five rows added (a gap label in light and Midnight, on a reversed axis and two close together, and the team-rider recipe at 340). v0.41.0 recorded 368 rows: v0.40.0's 360 reproduced exactly, with eight added (unpainted backgrounds, an app-averaged series, fitted bar heights, the fitted score-bars recipe). v0.40.0 recorded 360 rows: v0.39.0's 351 reproduced exactly, with nine added (gradient columns and bars, sub-labels, the lap and best-efforts recipes, the strip and end-label fixes). v0.39.0 recorded 351 rows: v0.38.0's 338 reproduced exactly, with thirteen added (strips, bars on tracks, undrawn titles). v0.38.0 recorded 338 rows: v0.37.0's 331 reproduced exactly, with seven added (set ticks, a unit, crowded end labels, the season arc and gap to the leader). v0.37.0 recorded 331 rows: v0.36.0's 325 reproduced exactly, with six added (averaged and windowed sampling, a pane without tick labels, the ride-channels recipe). v0.36.0 recorded 325 rows: v0.35.0's 318 reproduced exactly, with seven added (symmetric axes, signed labels, the fitness-and-form recipe). v0.35.0 recorded 318 rows: v0.34.0's 310 rows, 308 reproduced exactly in both finishes and two changed by design (`race/recommended-340-light` and `-midnight`, whose description now wraps to two lines), with 0.35.0's eight rows added (a finish-time histogram at 340 in light and Midnight and as a 1080 by 1350 card, bounds labels on Y, a reference in front of columns, and a long description, source and title at 340). Earlier releases changed rows by design: 0.31.0 the twenty graph rows, 0.30.0 the seven calendars drawn without `YZones`. Compare a new build with:

```bash
diff <(tr -d '\r' < reference/refined.txt) <(tr -d '\r' < baseline.txt)
```

When a release adds renderings, add their rows to `Program.cs` (named rows go in a block headed by the release that adds them) and, once the release is verified, replace the reference files with the new run.

The strongest check builds the previous release separately: `git worktree add <short path> v<previous>`, copy this folder into it, run it there, and compare that output with the current build's — rows that use API the old code lacks must be removed from the copy first. Keep the worktree path short; Windows refuses the long `obj` paths a deep one produces.

Hashes are recorded on Windows. Another platform's maths library can differ in the last bits of a sine or a logarithm, which moves an eighth decimal in a donut's arc, so compare hashes on Windows.
